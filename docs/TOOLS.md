# Tools and disk

What this project installs outside its own `Cargo.toml` / `package.json`, why,
and how to get the disk back.

Nothing here is needed to *use* detent — a release binary has no runtime
dependencies. This is the development and CI toolchain.

## What is required

| Tool | Needed for | Install |
|---|---|---|
| Rust 1.98.1 | everything | `rustup toolchain install 1.98.1` (pinned in `rust-toolchain.toml`) |
| [`bun`](https://bun.com) 1.4+ | the web console: package manager, script runner, **and test runner** | `curl -fsSL https://bun.sh/install \| bash` |

Rust alone builds and tests the CLI and the API. `bun` is needed only when
touching `web/`.

## What the checks need

Each of these backs a CI job, so a change that skips it locally fails there
instead.

| Tool | Backs | Install |
|---|---|---|
| `cargo-deny` | licence and advisory policy (`deny.toml`) | `cargo install cargo-deny` |
| `cargo-audit` | RUSTSEC advisories against `Cargo.lock` | `cargo install cargo-audit` |
| `cargo-llvm-cov` | the Rust coverage gate | `cargo install cargo-llvm-cov` |
| `cargo-cooldown` | the ADR-011 7-day supply-chain cooldown | `cargo install cargo-cooldown` |
| `cargo-fuzz` | the fuzz targets under `fuzz/` | `cargo install cargo-fuzz` (needs nightly to run) |
| `cbindgen` | the C-ABI header for the future `libdetent` | `cargo install cbindgen` |
| `shellcheck`, `shfmt` | `scripts/*.sh` | `brew install shellcheck shfmt` |
| `playwright` + Chromium | browser e2e and the axe pass | `cd web && bun install && bunx playwright install chromium` |

Two more are installed for the release pipeline (PLAN §6.3) but are not yet
wired into any workflow, so nothing fails today without them:

| Tool | Will back | Install |
|---|---|---|
| `cargo-auditable` | the embedded dependency list in release binaries | `cargo install cargo-auditable` |
| `cargo-cyclonedx` | the CycloneDX SBOM published with each release | `cargo install cargo-cyclonedx` |

`biome` is a `web/` dev-dependency; `bun install` provides it. There is no
separate `vitest`, `jsdom` or `@vitest/coverage-v8` install — see
[Test runner](#test-runner).

## Cross-compilation

Linux targets are cross-compiled from macOS with `cargo-zigbuild`, which uses
Zig as the linker.

```bash
uv tool install cargo-zigbuild
cargo zigbuild --release --target aarch64-unknown-linux-musl
```

`spikes/bin/zig` is a two-line shim that forwards to the `ziglang` Python
module `uv` installed, so `cargo-zigbuild` finds a `zig` on `PATH` without a
second copy of the toolchain.

Supported targets are x86_64 and aarch64 only, for Linux (musl) and macOS.

## Test runner

`web/` runs on **`bun test`**, not vitest.

```bash
cd web
bun test                 # 419 tests
bun run test:coverage    # plus the per-file line gate
bun run e2e              # Playwright + axe, against the built bundle
```

`bun test` needs three things Bun does not provide on its own, all set up by
`web/src/test/preload.ts` (wired in `web/bunfig.toml`):

1. **A DOM** — `@happy-dom/global-registrator` registers `document` and friends.
2. **Vite's `?raw` imports** — `src/i18n/index.tsx` loads the Fluent bundle that
   way, which Bun's resolver knows nothing about. A `Bun.plugin` loader reads
   the file and returns its text.
3. **jest-dom matchers** — installed with `expect.extend`; typed by
   `web/src/test/matchers.d.ts`, since `@testing-library/jest-dom` ships
   augmentations for Jest and Vitest but not for `bun:test`.

`bun test` resolves the `@/…` alias from the **root** `web/tsconfig.json` and
does not follow project references, which is why that file repeats the `paths`
mapping its two referenced projects already declare.

Playwright specs are named `*.e2e.ts`, not `*.spec.ts`: `bun test` claims
`*.spec.*`, and a Playwright spec picked up by the unit runner fails in a way
that reads like a broken test rather than a misrouted one.

## Where the disk goes

Measured on a working checkout; yours will differ.

| Path | Typical | What it is | Regenerated by |
|---|---|---|---|
| `target/` | 1–9 GB | Rust build output. Cargo never garbage-collects it, so a long-lived checkout accumulates objects for feature sets and dependency versions that no longer exist. | the next `cargo build` |
| `target/debug/incremental/` | 0.5–5 GB | incremental compilation cache | the next debug build |
| `target/llvm-cov-target/` | ~1.4 GB | coverage instrumentation | `cargo llvm-cov` |
| `web/node_modules/` | ~300 MB | web dependencies | `bun install` |
| `~/.bun/install/cache/` | ~2.6 GB | bun's global package cache, shared across projects | `bun install` |
| `~/.cargo/registry/` | ~350 MB | crate sources and `.crate` archives, shared | `cargo fetch` |
| `~/Library/Caches/ms-playwright/` | ~560 MB | browser binaries (`~/.cache/ms-playwright` on Linux) | `bunx playwright install chromium` |
| `~/.local/share/uv/tools/cargo-zigbuild/` | ~410 MB | `cargo-zigbuild` plus the Zig toolchain | `uv tool install cargo-zigbuild` |

## Cleaning up

`make clean` runs the cheap sweeps below in one step: incremental caches,
coverage builds, release and cross-compiled output, fuzz builds and crash
files, generated fuzz corpus, test reports, and debug files not touched for two
days (`STALE_DAYS=N` to change). It keeps the warm debug build and
`web/node_modules`, so the next build stays fast. `make realclean` removes
every ignored file except `.sops/` and `.mcp.json*`, plus the generated fuzz
corpus: the tree as if just cloned. Both take `DRYRUN=1` and `VERBOSE=1`;
`make du` shows what takes the space. The logic is in `scripts/clean.sh`.

Everything below is regenerable. The cost of a sweep is a slower next build,
never lost work. Ordered cheapest-to-recover-from first — stop when you have
enough space back.

**1. The incremental cache and coverage instrumentation.** Usually the largest
single win and the cheapest to lose.

```bash
rm -rf target/debug/incremental target/llvm-cov-target
```

**2. Stale object files.** Removes what is older than two days and leaves the
current build warm, so the next `cargo test` is still fast. This is what
`cargo-sweep` does; it needs no extra tool.

```bash
find target/debug -type f -mtime +2 -delete && find target/debug -type d -empty -delete
```

**3. Browser test artefacts.** Written on a failing Playwright run and never
cleaned up on their own.

```bash
rm -rf web/test-results web/playwright-report web/coverage
```

**4. All Rust build output.** Costs a full rebuild.

```bash
cargo clean
```

**5. Shared caches.** These belong to the whole machine — another checkout may
be relying on them.

```bash
rm -rf ~/.bun/install/cache                 # bun re-downloads on next install
cargo cache --autoclean                     # needs `cargo install cargo-cache`
rm -rf ~/Library/Caches/ms-playwright       # ~/.cache/ms-playwright on Linux
```

Check where you stand before and after:

```bash
du -sh . target web/node_modules
```

> Scratch scripts and one-off data belong in `/tmp`, not in the repo.
> `scripts/` holds helpers that CI or a documented workflow actually runs.

## Removing the toolchain entirely

```bash
cargo uninstall cargo-deny cargo-audit cargo-llvm-cov cargo-cooldown cargo-fuzz cbindgen
uv tool uninstall cargo-zigbuild
rm -rf ~/Library/Caches/ms-playwright ~/.bun/install/cache
rm -rf target web/node_modules
```

`rustup` and `bun` are left alone: they are general-purpose and almost
certainly predate this project.

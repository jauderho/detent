# libdetent — C ABI contract

> Status: Phase 10 (draft). Mirrors `crates/detent-ffi/src/lib.rs`. The
> header this describes is `include/detent.h`, generated by `cbindgen` and
> checked in.

`libdetent` is the public C ABI for `detent`'s pure core (PLAN §2.6, §10).
It exposes only the in-memory, no-I/O `ConfigModule` operations; file I/O,
process control and the operations layer live in the `detent-ops` binary
that links this library.

---

## ABI versioning

`detent_abi_version()` returns the compiled integer. The header pins it
as `DETENT_ABI_VERSION`. Mismatching the two is a SONAME mismatch and the
library must not be loaded.

| Library | SONAME        | `detent_abi_version` |
|---------|---------------|----------------------|
| 0.x     | `libdetent.so.0` | `0`                |

Bumping the version is a SONAME bump:

* Additive change (new function, new error code, new optional argument) →
  minor bump; old SONAME is kept.
* Source-breaking change (signature change, enum variant rename, struct
  layout change) → major bump; SONAME must change.

---

## Thread safety

Every function is safe to call from any thread, with one rule:

* `detent_last_error_message` is per-thread. Two threads must each call
  the FFI from their own thread to see their own errors.
* Doc handles returned by `detent_parse` are not shared state: each
  call returns a fresh handle, backed by a global `BTreeMap`. Free
  the handle from the same thread that created it. Concurrent
  `detent_free` on the same handle is racy.

Internal locking is three mutexes: the document-handle table, the live
hand-out set (every `detent_free` consults it before reading any tag
header, so foreign and already-freed pointers are refused without
touching memory), and the lazily-populated module registry (read-only
after the first call). The last-error slot itself is lock-free
thread-local storage.

## Memory ownership

| Producer | Consumer | Free via |
|----------|----------|----------|
| `detent_module_list`, `detent_render`, `detent_to_model_json`, `detent_apply_json`, `detent_validate_json`, `detent_defaults_json`, `detent_schema_json` | C string, NUL-terminated, JSON or text | `detent_free` |
| `detent_parse` | opaque document handle | `detent_free` |
| `detent_last_error_message` | borrowed `const char *`, valid until next FFI call on the same thread (the global slot may be overwritten) | copy if retained |

`detent_free(NULL)` is a no-op. The library tags every heap allocation
with an `AllocHeader` (`MAGIC_STRING` or `MAGIC_DOC`) directly preceding
the user-visible bytes; only pointers recorded in the live hand-out set
are eligible for a header read, so foreign and already-freed pointers are
refused before any memory is touched — the caller's pointer is not freed,
but the library never corrupts memory outside its own allocations.

Strings returned by the library are NUL-terminated; pass them to
`strlen` and `printf("%s", ...)` directly. Length parameters
(`src_len`, `model_len`, etc.) are byte counts; `strlen(...) ==
buffer_byte_count - 1` for the library's own strings, where the
trailing byte is the implicit terminator.

## Error handling

Every entry point returns a typed error code as the documented pattern:

| Returned shape | Success | Failure | Code |
|----------------|---------|---------|------|
| `*mut c_char` (string) | non-NULL | NULL | (see below) |
| `*mut c_char` (doc handle) | non-NULL | NULL | (see below) |
| `*const c_char` (last error) | text or NULL | — | — |
| `uint32_t` (abi version) | constant | not applicable | — |

Error codes on failure:

| Constant | Value | Meaning |
|----------|-------|---------|
| `DETENT_OK` | 0 | Success (mirrored from successful calls). |
| `DETENT_ERR_NULL_ARGUMENT` | 1 | A required pointer argument was NULL. |
| `DETENT_ERR_INVALID_UTF8` | 2 | A byte slice was not valid UTF-8. |
| `DETENT_ERR_UNKNOWN_MODULE` | 3 | The requested `module_id` is not in the registry. |
| `DETENT_ERR_PARSE` | 4 | `ConfigModule::parse` rejected the input. |
| `DETENT_ERR_MODEL` | 5 | A model JSON could not be deserialized, or a document could not be projected. |
| `DETENT_ERR_EDIT` | 6 | `ConfigModule::apply` rejected the edit. |
| `DETENT_ERR_INVALID_JSON` | 7 | A JSON input was syntactically invalid. |
| `DETENT_ERR_INTERNAL` | 8 | Allocation failed or an internal invariant was violated. |

There are no `errno`-style globals. All error context lives in
`detent_last_error_message`, which is per-thread and must be copied by
the caller if it is to be retained across further FFI calls.

The library never panics across the boundary; allocation failures and
shape mismatches are reported as codes or in the last-error buffer.

---

## Encoding

All `*const char` arguments are UTF-8 (the same encoding
`detent_core::Document::parse` accepts). Validity is checked at the
boundary; the error code is `DETENT_ERR_INVALID_UTF8` and the offending
field name appears in the last-error message.

JSON arguments and JSON returned by the library are the standard
`serde_json` serialization: UTF-8, no trailing newline, `null` for
absent values.

---

## Module registry

`detent_module_list` returns a JSON array of strings, one per module id
compiled into the library at build time (e.g. `["hosts","resolver"]`).
The set is fixed for a given build: enabling or disabling a module
rebuilds the library and produces a new SONAME if the ABI changed.

Module ids are stable strings (e.g. `"hosts"`, `"chrony"`). They are
the same ids the operations layer and the UI pass around; consumers
that round-trip through this library should treat them as opaque keys.

---

## Pointer discipline

A doc handle and a string are tagged by the same allocator; the magic
prefix is read by `detent_free` to decide what to drop. C code does not
have to know the tag, only that:

1. `detent_free(non-NULL)` is always safe, whether the pointer is one
   of ours or a foreign value.
2. Treating a foreign pointer as one of ours is detected and ignored
   (the foreign buffer leaks; it is not freed by the library).
3. Doc handles and string pointers are interchangeable to
   `detent_free` (the magic discriminates them) but never to other
   functions: passing a string to `detent_render` returns the wrong
   result because the tag check happens first.

## Build

```
cargo build -p detent-ffi --release
cbindgen --config crates/detent-ffi/cbindgen.toml \
         --crate detent-ffi --output include/detent.h

cc -I include examples/ffi-c/main.c target/release/libdetent_ffi.a \
   -lpthread -o /tmp/ffi-c-main
```

The release artifact is a `cdylib`, a `staticlib`, and an `rlib`
(PLAN §2.6 - `libdetent.so.0` + a static archive for embedding). The C
example output goes to `/tmp`, never in-tree: `examples/ffi-c/main` is a
compiled binary and must not be committed.

## CI

The `rust` job in `.github/workflows/ci.yml` covers `cargo fmt --check`,
`cargo clippy --workspace --all-targets --all-features`, and
`cargo test --workspace --all-features`, which include `detent-ffi`'s unit
and integration tests. Not yet wired (open Phase 10 work):
`cbindgen --verify` against `include/detent.h`, building and running
`examples/ffi-c/main.c` in CI, `cargo-semver-checks` on the crate, and a
Miri run on the FFI unit tests.

The C example exercises every FFI entry point against the `hosts` module
and a checked-in fixture, asserting that `detent_apply_json` on a model
derived from `detent_to_model_json(detent_parse(...))` round-trips
byte-for-byte.
